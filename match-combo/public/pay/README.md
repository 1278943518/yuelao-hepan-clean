# 收款码放这里

把两张收款码图片放进本目录，文件名必须完全一致：

| 文件名 | 内容 |
|---|---|
| `wechat.png` | 你的微信收款码 |
| `alipay.png` | 你的支付宝收款码 |

- 格式：PNG（JPG 也可以，但要把文件名改成 .png，或者在 app.js 里改后缀）
- 建议尺寸：正方形，500×500 以上，这样长按保存到相册后扫码清晰
- 微信收款码获取：微信 → 我 → 服务 → 收付款 → 二维码收款 → 保存收款码
- 支付宝收款码获取：支付宝 → 首页右上角「收钱」→ 保存图片

## 没放图会怎样

页面上会显示「待上传」的占位框，功能不报错，但用户没法付款。
上线前记得补上。

## 兑换码流程（你这边要做的）

用户扫码付款后，会点「我付好了，记一下订单」，生成一个订单号（形如 `YL...`）。

### 用管理页（推荐，手机也能操作）

打开 `<你的网址>/admin.html`，把 `ADMIN_TOKEN` 的值粘进去 → 「查看订单」。
待确认的订单一目了然，点「我已收到钱 · 出兑换码」就出码，
再点「复制发给用户的话」直接粘到微信发过去。

口令会记在这台设备上，下次打开自动加载。换手机或想清掉，点「清除口令」。

### 订单记录丢了怎么办（重要）

云端沙箱的文件系统是临时的，重启会把 `match/data/` 清空。但**不会因此丢了用户的码**：

- **订单号是自描述的**：`YL` + 套餐位（A=1次／B=5次／C=20次）+ 8 位时间 + 4 位随机，共 15 位。
  只看号码就知道这单买的是什么、该收多少钱，不需要查库。
- **兑换码是算出来的**，不是随机存的：`code = HMAC(密钥, 订单号)`。
  所以只要用户手里有订单号（在付款那一步的页面上，或者他截图发你的聊天记录里），
  在 `/admin.html` 底部的「凭订单号出码」粘进去就能重新算出**同一个码**。
- **用户那边也会自愈**：浏览器本地存着自己的订单和兑换码，
  打开页面时会自动重发一遍（`/api/claim`），服务端次数被清空也能自己补回来，不用找客服。

**建议配 `FEISHU_WEBHOOK`**：每一笔下单/出码/兑换都会推一条消息到飞书。
文件会丢、聊天记录不会 —— 那才是真正可靠的对账底账。

### 用接口（备用，方便脚本化）

1. 打开管理接口看有哪些待确认订单：
   ```
   GET  <你的网址>/api/admin/orders
   请求头：x-admin-token: <你设的 ADMIN_TOKEN>
   ```
2. 核对微信/支付宝到账后，把订单标为已付款并拿兑换码：
   ```
   POST <你的网址>/api/admin/confirm
   body: { "token": "<ADMIN_TOKEN>", "orderId": "YLB01234567ABCD" }
   → 返回 { "code": "7K3M9QXP" }
   ```
3. 把这串 code 发回给用户，用户在「有兑换码？」那一栏填入（连订单号一起），次数立刻到账。

只出码、不改状态（订单表丢了时用它把码找回来）：
```
POST <你的网址>/api/admin/code
body: { "token": "<ADMIN_TOKEN>", "orderId": "YLB01234567ABCD" }
```

一键体检（收款码能不能访问、口令对不对、白嫖口堵没堵）：
```
node scripts/pay_admin_e2e.js <你的网址>          # 完整跑一遍（会建一笔测试订单）
RO=1 node scripts/pay_admin_e2e.js <你的网址>     # 只读体检，不写数据
```

「服务端数据全被清空」的极端场景演练（会自动起隔离实例、删库、重启）：
```
node scripts/order_loss_repro.js
```

## 必须配置的环境变量

部署时要在环境变量里加：

```
ADMIN_TOKEN=<你自己定的一串口令，越长越好>
```

**不配的话管理接口整个关闭**（返回 403），避免别人乱改你的订单。
